# Architect

Architect is an optional world-authoring workspace registered through the normal module package system.

## Entering and leaving

Open the main menu, choose MODULES, select Architect in the installed-module list, then choose Enable Architect. The original HUD and viewer panels are hidden while the existing GPU world renderer remains the viewport. Use the red Turn off Architect control in the top toolbar to return to the normal viewer.

## Workspace

- Camera: use WASD to fly, Space/E to rise, Q/Ctrl to descend and Shift to boost. Hold the right mouse button and move the mouse to look around; release it to restore the normal editor cursor. Left-click remains reserved for panels and viewport tools. Escape opens the viewer menu.

- World (left by default): choose an empty project, any readable client map, or a saved Architect project. Client map changes use the viewer's existing world-handoff path and reopen Architect in the destination map.
- Client assets (right by default): browse the client folder tree lazily, expand PCK archive indexes on demand, and search the real member paths. The Asset Browser opens by default and can be reopened from the prominent toolbar button. Right-click a `.pck` file in the client tree and choose **Open in Asset Browser**, or select it to open its archive grid. The archive selector lists discovered game archives; choosing one opens a searchable asset grid with filters for ECM, SMD, BMD, GFX, SpeedTree and other files. Grid cards show the asset type, file name and stored/unpacked sizes. Right-click an asset card to pin it to the quick bar; the selected-asset details panel also has **Add to quick bar**. **Place at camera** uses the clicked/previewed asset directly and terrain-snaps its position. Hover or select entries to open a floating preview; moving the pointer from the grid into the preview keeps it alive. ECM models from `models.pck` and static SMD meshes from `gfx.pck` use the existing native model/material 3D preview with orbit, pan, zoom, animation and turntable controls. BMD scenery now renders an orbitable 3D preview using its decoded mesh vertices, indices, authored UVs, and diffuse textures from `building.pck` (or loose client files), multiplied by vertex/material lighting; missing texture references are listed below the preview. This is a lightweight preview, while actual placements still use the native baked-scenery material renderer. SpeedTree entries use the native tree instancer; GFX entries are played by the native effect owner/player and can publish their normal scene lights. Right-click grid cards, folders, files and archive entries to pin them to the quick bar. Unsupported files remain browse-only rather than being guessed into a renderer.
- Scene objects: inspect and viewport-pick loaded models, trees, scenery and effects; copy supported ECM/SMD models, BMD ornaments, SpeedTree types and catalogue-backed GFX effects into the editable project layer. Source map objects remain read-only; their editable copies live in the separate Architect project.
- Transform and hierarchy: custom ECM, SMD, BMD, SpeedTree and GFX placements appear in collapsible groups in the Transform panel. Each placement has an editable name and group, plus Visible and Locked flags. Groups have Select group, Hide, Show, Lock and Unlock actions. Multi-selection supports batch visibility, locking, assigning objects to the active object's group, aligning selected placements to the active placement on X/Y/Z, distributing three or more placements evenly along X/Y/Z, grounding selected objects to terrain, and resetting rotation or scale. Hidden placements are omitted from the live renderer and viewport picking; locked placements remain visible/selectable but cannot be moved. The hierarchy filter searches placement names and groups. Projects are written as PWA version 3; version 1 and 2 projects migrate on load, with per-axis scale defaulting to 1 for older projects. Selecting a source-scene item in the hierarchy or viewport now shows its transform gizmo; dragging a handle makes a project-owned copy first, preserving the immutable client map. The Transform panel also offers an explicit Make editable project copy action. Project placements receive a three-axis gizmo with camera-ray-constrained world-axis translation and ground-plane free translation. Rotation uses three distinct projected 3D rings (one per world axis), with pointer rays intersecting the selected ring's plane for stable axis-specific rotation. ECM/SMD/BMD placements have independent X/Y/Z scale handles that change only the corresponding scale component; SpeedTree and GFX retain their native uniform-scale handler. The uniform center drag and numeric controls remain available. Marquee and lasso select projected object bounds rather than only placement origins; they include source-scene objects and custom project placements. Active viewport gestures keep pointer capture when the cursor crosses editor panels. The Transform panel also has Select all, Clear selection, Duplicate selected and Delete selected actions. With multiple project placements selected, switch back to Select and drag on the terrain to translate the unlocked group together while preserving relative offsets. Group moves are committed as one object-history operation. Object edits have bounded undo/redo history; use Ctrl+C to copy selected project placements (or eligible selected source-scene models), Ctrl+V to paste independent copies with a small offset, and Delete/Backspace to remove selected project placements. The Transform panel exposes matching Copy, Paste and Delete controls. Its Transform snapping section can quantize gizmo movement, rotation and scaling independently (defaults: 1 world unit, 15 degrees and 5 percent); snapping is optional and disabled by default. Use Ctrl+Z to undo and Ctrl+Y or Ctrl+Shift+Z to redo when a text field is not active. History navigation clears placement selection and cancels any stale drag so restored list indices cannot silently target a different object. Supported ECM placements and static SMD meshes update in the live viewport through the native model/material GPU path; ECMs use the same animation and GPU queue as map models. BMD scenery, SpeedTree instances and GFX roots use their existing native renderer/owner handlers.
- Placement: select a supported ECM, static SMD, BMD scenery, SpeedTree or catalogue-backed GFX entry, then click the viewport. Placement raycasts against terrain first and falls back to a camera-height ground plane when the terrain sampler has no hit; the selected snapping mode is still applied. The floating preview also has a Place selected asset action for mesh formats. GFX effects appear through the native effect handler after placement rather than as a mesh ghost.
- Terrain tools: choose Sculpt in the viewport toolbar, then click-drag directly over terrain. A projected, terrain-conforming brush ring shows the active radius; raise/lower/flatten/smooth dabs follow the cursor and are saved as ordered brush operations. The camera-position brush remains available as a fallback. Height and normal overrides are shared with navigation and the renderer; the near terrain blocks and distant LOD rebuild when the edit revision changes. Brush strokes are stored in the project and support undo/redo. Paint is shown as an unavailable mode until terrain material painting is implemented.
- Quick bar (bottom): select pinned assets quickly.

The Multi-select cursor mode can select custom project placements and source-scene objects. Marquee and lasso are screen-space tests against projected object bounds, not depth-buffer occlusion tests; an object can be selected when any part of its projected bounds intersects the selection shape. Source-scene objects remain read-only until an explicit editable copy is created or a gizmo handle is dragged. Active marquee/lasso gestures retain pointer capture while crossing editor panels; changing tools cancels an unfinished gesture. Group names are currently flat labels (not nested parent/child folders); visibility and lock state apply per placement.

Panels are movable and can be repositioned to the left, right, bottom or floating placement. Directory and PCK indexes are cached until Refresh files is used.

## Project storage

Projects are saved as portable UTF-8 .pwa files under the user's application data directory:

- Windows: %LOCALAPPDATA%/PerfectWorldExplorer/Architect/Worlds
- Linux: $XDG_DATA_HOME/PerfectWorldExplorer/Architect/Worlds, or ~/.local/share/PerfectWorldExplorer/Architect/Worlds

The project format stores a source map ID, asset references, object transforms and ordered terrain-brush operations. Saves validate object/brush values and stage a temporary file while preserving the previous project as a rollback backup during replacement. Placements are not rendered when the active map does not match the project's source map. It is versioned and validates numeric values and file size on load. Loading a project replays its strokes over the immutable source terrain; undo/redo rebuilds that overlay from the stroke history.

## Current implementation boundary

The live project layer reuses the existing native handlers: ECM models from `models.pck` and static SMD meshes from `gfx.pck` use the model/material renderer; BMD ornaments use the baked-scenery builder; SpeedTree types use the GPU tree instancer; and catalogue-backed GFX roots use the native effect owner/player and light-publication queue. All four families are stored as ordinary project placements and can be selected, transformed, copied, pasted, hidden, deleted and undo/redo'd without losing their original client asset references. GFX effects render after placement and are reconciled after a transform gesture, avoiding effect reloads on every drag frame. Unsupported building formats, textures and unrecognized archive entries remain browseable and pinnable; they are never guessed into a renderer. Terrain sculpting is a sparse, non-destructive in-memory overlay: it updates heights and recalculated normals for the shared navigation/renderer data, and forces both resident near terrain and distant LOD to rebuild. It never modifies the client's original T2BK/ECWLD files. Paint/material editing and native map export remain unavailable until validated material, ECWLD, EC-BSD and terrain writers exist.
