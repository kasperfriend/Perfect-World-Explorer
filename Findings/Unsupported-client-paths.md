# Known unsupported or incompletely reproduced client paths

Updated 18 November 2026 against the current branch. (Originally 2 November 2026, revision `a9c4b35`.) This is an explicit
**nonempty** register, not a claim of an exhaustive asset census. Unknown paths
may still be discovered. Per-requirement evidence and remaining acceptance are
in the [76-point reassessment](Eight-phase-reassessment-2026-11-02.md).

| Controller-108 LUT construction precision | Resolved to PC24. | Terrain layer `type` byte | **Separated: it is a renderer-visible selector, and it is *not* the projection axis.** The native build copies the whole 28-byte record into its own 36-byte draw entry (`0x7a2579..0x7a259e`, byte `+0xc` → entry `+0xc`) and calls `0x77f180` with that entry's first dword. Disassembled, `0x77f180` never reads byte `+0xc`: it tests the object's own `+0x178` flag, dereferences the texture pointer at `[esi]`, and either acquires it through `0x77c230` or returns the cached id at `[esi+4]`. A whole-image scan (1,750,808 disassembled instructions) finds `movzx` of `+0xc` exactly once, at `0x8213e1`, inside a byte-summing hash loop over a 16-byte block — not a per-layer consumer. So the byte reaches the renderer but nothing branches on it in this image. The viewer now keeps the two apart: `material::Layer::selector` is the authored byte, untouched and readable, and `axis` is the projection rule the shaders use, derived 1:1 from it (selectors 0/1/2 → the z/y, ground and x/y planes, values measured as 0/1/2 in `world_39.t2mk` and `world_88.t2mk`). ## Other client versions (data-version reporting, 18 November 2026)

The folder scan now reports three things separately instead of comparing the
folder with one 1.4.2 fingerprint: the executable (size, SHA-256, PE32 machine,
`VS_VERSIONINFO` strings), the **data version as the `(elements.data,
tasks.data)` pair**, and every archive's container version. A version that is
not 1.4.2 is reported, not refused — these rows name what is still missing for
older and newer clients.

| `elements.data` record layout beyond v27 | Only v27 (`0x3000_001b`) is parsed. The scan reports the revision it finds (the low 16 bits of the header word, e.g. `v29 (0x3000001d)` for the RUS 1.4.2 data, `v267` for CN 1.6.6), and `Catalog::parse_v27` / `visit_v27_records` refuse the tables with that version named. The record sizes and section table of v6/v12/v13/v70/v85/v253/v267 releases are **not** decoded; their section counts and record strides differ from v27 and are not guessed. | Instance precinct coordinate frame | **Resolved: one frame, centred on the origin.** An instance map's `.trn2` carries no world transform (header words 84..96 are zero) and its extent words are *sizes*, not a corner, so a map `width` x `length` covers `-width/2 ..= width/2` in both x and z. | Instance aliases for b07-b29 | **Not a defect: an absent input.** `configs/instance.txt` in the 1.8.4 archive lists 68 rows across 65 folders, and **none** of `b07`-`b29`; the arena folders it lists are `b01`-`b04` and the six `b30` territory-war rows. | Precinct ambience priority | **The client's precinct reader is now located, but the header-index mapping is not.** `0x654320` in the 1.4.2 `elementclient.exe` is `CELPrecinct::Load`: it opens `AString` with `"\\precinct.clt"` appended to the map path (`0x4298f9`), reads the version (`cmp ebp,6` / `jl`, `0x654dc1`), and then parses each zone with a repeated `seek(+1)/read` sequence, storing successive numbers into `+0x40`, `+0x54`, `+0x68`, `+0x58`, `+0x50`, `+0x44` and `+0x48`. The selector `0x654cb0(x,z)` matches a zone only when `[zone+0x54]` equals its third argument (`0x654ccb`) and then keeps the candidate whose `+0x58` is not smaller (`0x654cec`/`0x654cef`) — its callers pass that class from player state (`0x42c980`, `0x519197`), not from a file constant. **What is still open is which file index lands in `+0x54`.** The parse loop is stdcall with a locally-balanced stack, so static offsets cannot be assigned to indices without modelling each callee's argument count; the candidate readings are index 3 as the class and index 8 as the group, or index 3 as a group with the class held elsewhere. The 1.8.4 world file supports the first reading only weakly: index 3 takes values 0 (53 zones), 1 (38), 2 (22), 3 (102), 4 (168), while index 8 is **1 for all 383 zones**, so a group tie-break on index 8 would never fire in the measured corpus and the second reading cannot be excluded from data alone. Index 5 does vary inside a class (0..4), which is why it is the other candidate. The viewer therefore still plays the zone's one stereo pair and invents no priority; what changed is that the row now says which function decides, which addresses were read, and exactly which step is missing, instead of "the disassembly that reads it has not been found". Measured with `tools/offline_harness.sh music`. | P6 |

| Audio codec coverage | **Answered for the staged corpus; this is a watch item, not a gap.** `rodio` is built with `mp3`, `vorbis` and `wav`, and the corpus uses exactly those: the 1.8.4 `precinct.clt` references 746 `.mp3`, 692 `.wav` and 37 `.ogg`, and `configs/sound.txt` is 60 `.wav`. ## Completion policy

P8.10's **tracking/policy deliverable** is implemented by maintaining this register;
that does **not** mean its entries are resolved. P8.01's exhaustive census and
resolution requirement remains incomplete. Do not claim 100% parity while this
register has open entries, while the census is incomplete, or while full-scope
acceptance gates remain open. Removing rows, renaming gaps, or passing compilation
cannot satisfy that condition. Close entries only with implemented behavior and
specific validation evidence.

This register records behavior-level gaps. Existing named asset/dependency failure
reporting in `world_models.rs` and client survey manifests remains necessary;
this document does not replace a complete per-asset failure census.
