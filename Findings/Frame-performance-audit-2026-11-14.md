# Viewer performance audit — 14 November 2026

## Evidence boundary

The user reports low FPS despite strong hardware and little change when water reflections are disabled. Those facts do not isolate a CPU, GPU, or presentation bottleneck. There is no representative target-machine capture in this workspace. `PW_FRAME_TIMING=1` reports CPU wall time around surface acquisition, world/map submission, and presentation; it explicitly does **not** measure GPU execution. Therefore this audit distinguishes repeated work visible in code from a measured bottleneck, and makes no FPS or utilization claim.

## Substantial code-path costs and exact fixes

| # | Evidence in the viewer | Exact fix | Status / what is known |
|---|---|---|---|
| 1 | `world_models_gpu::advance_poses`, `draw_models`, and `rebuild_alpha_order` walked the complete `Assets::instances`/slot set and tested every placement against resident terrain bounds on steady-state frames. Large maps retain many out-of-window placements. | Build an ordered resident-slot index only when the terrain bounds change; use that list for pose evaluation, model uploads, and alpha-candidate collection. Keep the full slot table for identity/attachments and evict out-of-window draws as before. | Implemented in the current working diff. Semantics use the same half-open `cutoff_residency::contains` test; reduces visited slots from total placements to resident placements after window changes. No measured timing yet. |
| 2 | `apply_activation` created and filled a fresh `Vec<(identity, active)>` for every producer each main-frame update, then immediately traversed it to call `Manager::set_active`. | Compute each producer's near/resident/day-night gates and call `set_active` in that same loop; keep the three census counters, but remove the temporary vector and second pass. | Implemented in the current working diff. Exact gate conditions and census are unchanged. Allocation/time impact not measured. |
| 3 | The scenery-object view path previously tested all placed meshes against each view's bounds; this is repeated across scene views and is not proportional to visible objects. | Query the worker-built BVH using conservative placement AABBs; retain invalid/missing bounds conservatively and restore original placement order before building opaque/SDR lists. | Implemented earlier in this branch (`6dbd002`, formatting follow-up `94cd2f9`). Preserves whole-world availability and draw order. No FPS improvement is claimed. |
| 4 | The camera-centred realistic minimap previously submitted the entire water index range, although it only displays a small local window and the renderer already owns spatial water batches. | Select conservative visible water batches for the local minimap; retain all batches for the full-world map. | Implemented earlier in this branch (`cf2ad75`). Reduces off-window water submission/raster work for the minimap without reducing its visible extent. No measured gain. |
| 5 | The opaque model mesh loop used linear `Vec::contains` against the alpha-mesh list for every mesh, giving O(meshes × alpha meshes) membership checks. | Use binary search on the already ascending alpha-mesh indices, or a precomputed membership bitset if later profiles show this loop still matters. | Binary search implemented earlier in this branch. It preserves mesh order and changes membership work to O(meshes × log(alpha meshes)); magnitude unmeasured. |
| 6 | Each world-model pass calls `draw_one` for every resident model; it repeats `StaticGrid::query(position, night)` and queues constant updates even when only the pass camera matrices differ. Reflection/refraction passes reuse scene-light publications and positions. | Measure this stage first; if material, cache each model's point-light assignment for the frame after the main grid update, while still updating view-dependent constants for each pass. Invalidate on grid/light generation or night-factor changes. | Confirmed repeated code path, not yet established as a dominant cost. Not changed because correct invalidation must account for per-frame dynamic lights and is not presently instrumented separately. |
| 7 | `rebuild_alpha_order` reconstructs candidates and sorts all resident alpha meshes once per advancing frame, including frames where the eye is unchanged. | Retain the previous eye/order and skip the rebuild for an identical eye; invalidate on eye change, resident-window changes, draw creation/failure, or alpha-mesh changes. | Exact optimization opportunity from code inspection; not implemented. It only helps stationary-eye frames, so expected value depends on usage and candidate count. |

The first five entries above are concrete repeated work and exact fixes, not claims that each is currently the user's limiting stage. Three of the fixes predate this deeper pass; the first two are new implementation work in the current diff. Entries 6–7 are explicitly labeled as unmeasured follow-ups rather than padded findings.
