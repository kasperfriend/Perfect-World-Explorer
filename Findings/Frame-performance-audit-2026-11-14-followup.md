# Viewer performance audit — fresh follow-up

This follow-up contains **only new, not-yet-implemented optimization options**. It excludes the earlier audit’s findings and excludes the boosts implemented in this pass. These are repeated costs visible in code, not measured rankings; each row gives a concrete fix. No FPS gain is claimed without a representative capture.

## Ten new options to investigate

| # | New cost found | Exact fix | Evidence / caution |
|---|---|---|---|
| 1 | `StaticGrid::update` compares the full cached static-light vector with `lights.lights` on nearly every frame while the camera remains in the same 12-unit cell. | Make the loaded light corpus immutable or revisioned, then rebuild only when its revision changes or the existing cell-window threshold is crossed. Do not substitute pointer identity while public in-place mutation is allowed. | `src/scene_lights.rs`, `StaticGrid::update`. Exact invalidation needs an API contract; scene-light record count and time are unprofiled. |
| 2 | `GpuPage::draw_commands_pair_visible` constructs temporary opaque and SDR `PageSpans` vectors per view, in addition to returning fresh command vectors. | Fold directly over `GpuPage` placement/SDR ranges, or keep reusable page-span and command scratch buffers in `Renderer`; retain original placement order and pass admission. | `src/world_objects.rs`, `draw_commands_pair_visible`; called through `Renderer::world_commands_for_view` in `src/gpu.rs`. |
| 3 | For visible complex water, Main and Refraction command generation use the same matrix but independently compute and sort world visibility. | Compute the visible-order list once for that matrix, then fold it into distinct Main and Refraction command lists. | `src/gpu.rs`, `render` / `world_commands_for_view`. Benefit scales with whole-world placement count and visible-water frequency. |
| 4 | Active post-processing creates fresh texture views and bind groups for stable attachments every post frame. | Cache the fixed scene/fogged/warped/downsample/blur views and finite input-pair bind groups when post targets are allocated or resized; choose among them per post plan. | `src/post_gpu.rs`, `PostGpu::render`. Must invalidate bindings on resize and preserve the existing raw/sRGB view choices. |
| 5 | A tree camera-key change dispatches the LOD compute shader over every placement, including placements outside the camera’s view/far range. | Build conservative spatial bins and dispatch only bins whose expanded bounds may enter the current view/far range; use a tree-size halo and verify the result against the CPU LOD reference before enabling. | `src/far_trees_gpu.rs`, `update_resident_lods` / `LOD_COMPUTE`. Must not drop trees that can reach the view; whole-world visibility remains the constraint. |
| 6 | Weather’s vertex shader recomputes camera-relative particle positions, hashes, and billboard corners for every rendered view, though the particle set/clock is shared for the frame. | Generate one per-frame particle-instance buffer and reuse it across main/reflection/refraction views; keep view matrix, clip, and fog per pass, and compare deterministic output against the current shader. | `src/weather_gpu.rs`, `SHADER` and `WeatherGpu::draw`. This trades repeated shader work for one generation/upload; GPU and CPU costs need measurement. |
| 7 | Water render-target `TextureView`s are recreated when complex water is visible, despite the underlying textures remaining fixed until resize. | Store the default/raw views alongside `WaterTargets` and rebuild them only in target creation/resize; borrow those views during passes. | `src/water_gpu.rs`, `reflection`, `depth`, `refraction`, `scene` view accessors. Measure CPU impact; this is not expected to change pixels. |
| 8 | `draw_opaque` ends the terrain render pass and opens a second scenery pass even when no terrain-depth copy is needed between them. | When `terrain_depth_source` is `None`, keep one render pass open and switch from terrain to tree/grass/scenery pipelines within it; keep the split path when the water-edge depth copy is required. | `src/gpu.rs`, `Renderer::draw_opaque`. Validate load/clear, depth, and ordering equivalence for every view. |
| 9 | `render_scale.blit` submits a full-resolution fullscreen pass every frame, including native 100% scale where source and composition extents match. | Add a direct-render route only when scaled extent equals output extent, renderer/target formats are compatible, and no composition transform is required; retain the existing blit for scaling and incompatible presentation paths. | `src/render_scale.rs` and the main loop in `src/gpu.rs`. Display-gamma and present-encode intermediates make the direct-route gate essential. |
| 10 | Water visibility still tests every static batch’s AABB against the frustum each frame before sorting. | Build a static BVH/grid over water-batch bounds and query it with the view frustum, then keep the current far-to-near ordering for the returned set. | `src/gpu.rs`, `WaterBatch::visible` and `Renderer::render`. Worth implementing only if water-batch counts justify the index. |

## New boosts applied in this pass

- Moved submerged-weather rejection to the CPU’s existing active-water-mask result and removed the per-particle-vertex water-area/mask scan and its two storage buffers.
- Submitted only the selected rain/snow instance range.
- Removed per-frame staging allocations from attenuation and normal attachment resolution; switched current-frame dynamic-light publication lookup to an identity map and reused its consume scratch buffer.
- Cached each visible water batch’s distance once for far-to-near sorting, replaced batch clones with indices, and bypassed the full water scene/refraction/depth/blit path when no visible complex-water batch needs it. Terrain-edge depth is copied only when a visible reflected plane needs that pass; reflection/refraction/depth views are created only for visible complex reflective water.

## Implementation status for the ten listed options

This status tracks only the ten rows above; no additional optimization candidates were searched for.

| # | Status and documented change |
|---|---|
| 1 | **Implemented, not yet validated.** `SceneLights.lights` and the grid's retained corpus are immutable `Arc<[SceneLight]>` snapshots. `StaticGrid::update` uses snapshot identity plus the existing camera-cell threshold; `SceneLights::from_lights` is the replacement/construction API. |
| 2 | **Implemented, not yet validated.** `GpuPage::draw_commands_pair_visible` now folds directly from page placement/SDR ranges and no longer allocates the two temporary `PageSpans` vectors per call. |
| 3 | **Implemented, not yet validated.** Main and refraction command generation reuse one frustum-visible placement-order list because both use the same matrix. The pass-specific admission and command folds remain separate. |
| 4 | **Implemented, not yet validated.** `PostGpu` caches the fixed attachment views and ten finite texture-pair bind groups. It invalidates and rebuilds them on resize; post targets keep their raw/sRGB view choices. The stable renderer depth target is captured in those groups on first active use and the resize path invalidates them with the depth target. |
| 5 | **Implemented, not yet validated.** Far-tree placements are binned once in 128-unit XZ cells. On a changed camera key, only indices from bins intersecting the existing resident bounds are uploaded and dispatched; the shader still applies its exact old bounds test and original placement order is restored before dispatch. A broad or malformed bound falls back to all placements. |
| 6 | **Implemented, not yet validated.** A compute pass generates the deterministic rain/snow billboard centers and dimensions once on the first weather draw of each frame into a shared storage/vertex buffer. Main/reflection/refraction draws reuse it; each view still supplies its own matrix, clip and fog uniform. The generation expressions were moved without changing their constants/formulas. |
| 7 | **Implemented, not yet validated.** `WaterTargets` now retains the default and raw/sRGB-compatible attachment views (and depth views); accessors borrow those cached views instead of recreating them per frame. Resize recreates them with the targets. |
| 8 | **Implemented, not yet validated.** `draw_opaque` now keeps terrain and scenery in one render pass when no terrain-depth copy is requested. The split pass and terrain-only copy remain for the water-edge case. |
| 9 | **Implemented, not yet validated.** The main loop directly renders to the swapchain only when extents and formats match and neither whole-frame gamma nor present encoding requires an intermediate; otherwise the existing scaled target and blit remain. |
| 10 | **Implemented, not yet validated.** Static water-batch bounds are indexed once with the existing world BVH; each frame queries the frustum and then keeps the existing far-to-near distance sort. |
