# Viewer performance audit — fresh follow-up

This follow-up contains **only the ten optimization options in scope**. It excludes the earlier audit’s findings and excludes the boosts implemented in that earlier pass. These are repeated costs visible in code, not measured rankings; each row gives the concrete fix. No FPS gain is claimed without a representative capture.

## Ten options and implementation status

| # | Cost found | Exact fix | Implementation and code-path evidence |
|---|---|---|---|
| 1 | `StaticGrid::update` compares the full cached static-light vector with `lights.lights` on nearly every frame while the camera remains in the same 12-unit cell. | Make the loaded light corpus immutable or revisioned, then rebuild only when its revision changes or the existing cell-window threshold is crossed. Do not substitute pointer identity while public in-place mutation is allowed. | **Implemented.** `SceneLights.lights` and the grid’s retained corpus are immutable `Arc<[SceneLight]>` snapshots. `StaticGrid::update` checks snapshot identity plus the existing camera-cell threshold; `SceneLights::from_lights` is the replacement/construction API. `src/scene_lights.rs`. |
| 2 | `GpuPage::draw_commands_pair_visible` constructs temporary opaque and SDR `PageSpans` vectors per view, in addition to returning fresh command vectors. | Fold directly over `GpuPage` placement/SDR ranges, or keep reusable page-span and command scratch buffers in `Renderer`; retain original placement order and pass admission. | **Implemented.** `GpuPage::draw_commands_pair_visible` folds directly over placement/SDR ranges, removing both temporary `PageSpans` vectors per call. `src/world_objects.rs`; called through `Renderer::world_commands_for_view` in `src/gpu.rs`. |
| 3 | For visible complex water, Main and Refraction command generation use the same matrix but independently compute and sort world visibility. | Compute the visible-order list once for that matrix, then fold it into distinct Main and Refraction command lists. | **Implemented.** Main and refraction command generation reuse one frustum-visible placement-order list for their identical matrices. Pass-specific admission and command folds remain distinct. `src/gpu.rs`, `render` / `world_commands_for_view`. |
| 4 | Active post-processing creates fresh texture views and bind groups for stable attachments every post frame. | Cache the fixed scene/fogged/warped/downsample/blur views and finite input-pair bind groups when post targets are allocated or resized; choose among them per post plan. | **Implemented.** `PostGpu` retains fixed attachment views and ten finite texture-pair bind groups, rebuilding on resize while preserving raw/sRGB choices. Stable renderer depth is captured on first active use and invalidated alongside depth targets on resize. `src/post_gpu.rs`. |
| 5 | A tree camera-key change dispatches the LOD compute shader over every placement, including placements outside the camera’s view/far range. | Build conservative spatial bins and dispatch only bins whose expanded bounds may enter the current view/far range; use a tree-size halo and verify against the CPU LOD reference. | **Implemented.** Far-tree placements are binned once into 128-unit XZ cells. A changed camera key queries cells intersecting resident bounds and the camera’s far range expanded by the maximum tree-mesh halo; only those ordered indices are uploaded/dispatched, with the exact resident-bounds test retained in WGSL. Placement records and the appended active-index list share one storage buffer to stay within downlevel devices’ four compute-storage-buffer limit. Broad/malformed bounds conservatively fall back to all placements. `src/far_trees_gpu.rs`; GPU checks include `src/bin/tree-lod-gpu-check.rs`. |
| 6 | Weather’s vertex shader recomputes camera-relative particle positions, hashes, and billboard corners for every rendered view, though the particle set/clock is shared for the frame. | Generate one per-frame particle-instance buffer and reuse it across main/reflection/refraction views; keep view matrix, clip, and fog per pass, and compare deterministic output against the current shader. | **Implemented.** A compute pass generates deterministic rain/snow billboard centers and dimensions once on the first weather draw each frame into a shared storage/vertex buffer. Main/reflection/refraction reuse it; each view retains its own matrix, clip and fog uniform. Generation expressions preserve their original constants/formulas. The obsolete render-vertex `hash` helper was removed while the compute shader’s hash remains. `src/weather_gpu.rs`. |
| 7 | Water render-target `TextureView`s are recreated when complex water is visible, despite the underlying textures remaining fixed until resize. | Store the default/raw views alongside `WaterTargets` and rebuild them only in target creation/resize; borrow those views during passes. | **Implemented.** `WaterTargets` retains default and raw/sRGB-compatible attachment views (and depth views); accessors clone shared `Arc` handles instead of recreating views per frame. Resize recreates the cached views with the targets. `src/water_gpu.rs`. |
| 8 | `draw_opaque` ends the terrain render pass and opens a second scenery pass even when no terrain-depth copy is needed between them. | When `terrain_depth_source` is `None`, keep one render pass open and switch from terrain to tree/grass/scenery pipelines within it; keep the split path when the water-edge depth copy is required. | **Implemented.** `draw_opaque` keeps terrain and scenery in one render pass when no terrain-depth copy is requested. The split pass and terrain-only copy remain for the water-edge case. `src/gpu.rs`. |
| 9 | `render_scale.blit` submits a full-resolution fullscreen pass every frame, including native 100% scale where source and composition extents match. | Add a direct-render route only when scaled extent equals output extent, renderer/target formats are compatible, and no composition transform is required; retain the existing blit for scaling and incompatible presentation paths. | **Implemented.** The main loop directly renders to the swapchain only when extents and formats match and neither whole-frame gamma nor present encoding requires an intermediate; otherwise the existing scaled target and blit remain. `src/render_scale.rs`, `src/gpu.rs`. |
| 10 | Water visibility still tests every static batch’s AABB against the frustum each frame before sorting. | Build a static BVH/grid over water-batch bounds and query it with the view frustum, then keep the current far-to-near ordering for the returned set. | **Implemented.** Static water-batch bounds are indexed once with the existing world BVH; each frame queries the frustum and then keeps the existing far-to-near distance sort. `src/gpu.rs`, `WaterBatch::visible` and `Renderer::render`. |
